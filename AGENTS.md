## Non-negotiable boundaries

- Local-first is the trust root. Strict-local mode has no hidden cloud fallback and must enforce network egress at the kernel-authorized choke point.
- Rust is mandatory for the trusted runtime, daemon, CLI/TUI, policy, durability, secrets, device transport, remote-control broker, model routing, memory orchestration, audit, and protocol authority.
- The broader Rust trusted path is NOT the same as the privileged kernel. Only the smaller privileged kernel may own/mutate authority state, mint capability material, authorize effects/egress, broker secrets, authenticate local clients, or sign security-critical records.
- Localhost/same-machine presence is not authentication. Every local client must authenticate.
- TypeScript is permitted only in the untrusted Tauri renderer and other explicitly untrusted UI surfaces.
- Python/Node integrations may exist only as optional sandboxed adapters; they cannot become required for strict-local operation.
- `Golam-Research` and reconstructed Grok Bot material are behavioral/reference evidence only. Do not copy reconstructed proprietary material into Golam.
- No donor code/dependency enters Golam merely because it is listed or snapshot-verified. The owning implementation spec must perform exact Source Foundry admission.
- GPL/AGPL/SSPL and similarly reciprocal donors are reject-code/reference-only by default unless the founder explicitly approves bounded license obligations.
- A model, skill, MCP server, channel, worker, client, or remote device can request authority but cannot grant/expand its own authority.
- Protected policy/principal/lease/secret/audit/effect/pairing/egress/skill-lock/schedule state cannot be mutated through generic filesystem tools.
- All consequential effects must pass the Effect Gate, persist intent before dispatch, honor handler/reconcile semantics, and produce durable evidence.
- UNKNOWN_OUTCOME blocks dependent effects; AT_MOST_ONCE/IRREVERSIBLE effects never blind-retry.
- Taint can only downgrade through explicit human approval or registered deterministic authoritative verification; generated artifacts inherit taint.
- Never claim a benchmark, CI, security, parity, offline, platform, or reliability gate passed without exact-head evidence.

## Development discipline

- Work in small Spec Kit task slices.
- Preserve exact-head verification.
- Start the Rust workspace with at most eight real crates/binaries; do not scaffold an empty 20+ crate architecture.
- Use cargo fmt/clippy/test as default Rust gates, plus property/fuzz/fault-injection/security tests for the owning spec.
- Safety/durability/no-egress gates start early; do not defer them to Spec 010.
- Prefer reversible changes, explicit contracts and independent PRs over broad rewrites.
